# E. Does the byte parser run OCR

Open question E of the exploration (`.claude/work/2026-11-23_27_pipeline-refresh/exploration.md`,
section 6.3).

## What was found

`pymupdf4llm.to_markdown` runs OCR by default (`use_ocr=True`). On this machine the library
chose Tesseract from `/usr/bin/tesseract`, which is outside `.venv`, and ran it on page 0 of
both test files. On a machine without Tesseract the same PDF gives other text and another
hash, so the build would see a "changed" document.

## The options

1. Keep OCR on, pass the options explicitly, and record them in the row's `meta`.
2. Turn OCR off, so that the text does not depend on the machine.

## The answers

**2026-11-25, decided by the lead assistant session `ema-nlp-3b` under the owner's delegation
of 2026-11-25** ("You are allowed to plan and implement ways forward"), relayed to the
implementing session. This is the assistant's answer, not the owner's. The owner can overrule
it.

Option 1, the recommendation. It is closest to how the legacy text was made. The parser passes
`use_ocr`, `header` and `footer` explicitly and records them in `meta`, with the versions of
`pymupdf4llm`, `pymupdf` and `pymupdf-layout`. Whether OCR helps is row 17's question.
